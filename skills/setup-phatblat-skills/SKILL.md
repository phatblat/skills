name: setup-phatblat-skills
description: Run only when the user explicitly invokes setup-phatblat-skills. Records the repository's changelog policy and versioning scheme in AGENTS.md so the recording-changes and semantic-versioning skills stop guessing.
license: MIT
disable-model-invocation: true
---

1. **Precondition.** Stop unless the user explicitly asked to run
   `setup-phatblat-skills`. Never infer permission from repository state, an
   incomplete changelog policy, or the presence of sibling skills.
2. **Explore** (read, do not assume): `git remote -v`; whether `AGENTS.md` and
   `CLAUDE.md` exist and whether either already has an `## Agent skills`
   section; whether `CHANGELOG.md` exists; release automation signals
   (`.releaserc*`, `.changeset/`, `.changes/`, `release-plz.toml`,
   `[workspace.metadata.release]`, a `release-please` config, or a
   `CHANGELOG.md` carrying a generator's marker line); `git tag --list` for the
   tag shape and prefix; the package manifest's version field; and which of
   `recording-changes` and `semantic-versioning` are available as skills.
3. **Ask, one section at a time, recommendation first.** Skip section A when
   the `recording-changes` skill is unavailable, skip section B when
   `semantic-versioning` is unavailable, and if both are skipped, say there is
   nothing to configure and stop. In a non-interactive session, do not ask:
   apply the detected default for each section and name the defaults used.

   **Section A, changelog policy.** Default to what exploration found: release
   automation present → generated; a `CHANGELOG.md` with no automation →
   hand-curated; neither → none. Write exactly one of these lines:

   ```markdown
   - **Changelog**: `CHANGELOG.md` is hand-curated under [Keep a Changelog 2.0.0](https://keepachangelog.com/en/2.0.0/); add entries under `## [Unreleased]`.
   - **Changelog**: `CHANGELOG.md` is generated by <TOOL> from <SOURCE>; never edit it by hand.
   - **Changelog**: this project keeps no changelog; do not create one without asking.
   ```

   **Section B, versioning scheme.** Default to Semantic Versioning unless the
   tags say otherwise (a date-shaped tag means CalVer). Write exactly one of:

   ```markdown
   - **Versioning**: releases follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html); tags are `<PREFIX>x.y.z`. The public API is <API>.
   - **Versioning**: releases use CalVer (`<PATTERN>`); the semantic-versioning skill's bump table does not apply.
   - **Versioning**: <one line the user dictates>.
   ```

   `<API>` is what the user names as the declared public API (SemVer rule 1
   requires one); if they have not declared one, write `not yet declared` and
   say that bump decisions are guesses until it is.

4. **Confirm.** Show the assembled block and let the user edit it before
   writing.
5. **Write.** Target `AGENTS.md`, always: it is the canonical, tool-agnostic
   instruction file. Update an existing `## Agent skills` section in place
   rather than appending a second one, and touch nothing else in the file. If
   `AGENTS.md` is absent, create it with a `# Repository Guidelines` heading
   and the block. If `CLAUDE.md` exists and does not already import
   `AGENTS.md`, offer to add `[@AGENTS.md](AGENTS.md)` as its first line (the
   `@` is what Claude Code imports; the link is what a human clicks) rather
   than duplicating the block.

   The block:

   ```markdown
   ## Agent skills

   From [phatblat/skills](https://github.com/phatblat/skills).

   - **Changelog**: …
   - **Versioning**: …
   ```

6. **Done.** Say which skills now read the block, that `authoring-skills`
   needs no per-repo configuration, and that the block can be edited directly
   later; re-running is only for switching policies.
